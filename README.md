# WebApp Project — Practical DevOps CAT

A small Node.js web application prepared to support the practical tasks for Jira, Git/GitHub, Docker, Jenkins, Kubernetes, and GitHub Actions.

## Requirements

- Node.js 22 or later
- npm
- Git
- Docker Desktop
- Jenkins with Node.js, npm, Git, and Docker available to the agent
- Kubernetes enabled in Docker Desktop for the Kubernetes task

## Run locally

```powershell
npm install
npm test
npm start
```

Open http://localhost:3000.

Health check: http://localhost:3000/health

## Q3 — Initialize Git

Run these commands from this project directory:

```powershell
git init
git add .
git commit -m "Initial commit"
git branch -M main
```

Create a GitHub repository, then connect and push it:

```powershell
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

Replace the URL with your own repository URL.

## Q4 — Branch and merge

```powershell
git switch -c feature-login
```

Create or update `public/login.html`, then:

```powershell
git add .
git commit -m "Add login page"
git switch main
git merge feature-login
git push origin main
git push origin feature-login
```

## Q5 — Pull request

For the assignment demonstration, push `feature-login` and create a pull request on GitHub with:
- base: `main`
- compare: `feature-login`

Review at least:
1. The changed files and whether the login page works as expected.
2. The code for errors, missing validation, or unintended changes.

If you merge the PR on GitHub, update your local main branch:

```powershell
git switch main
git pull origin main
```

## Q6 — Jira/GitHub integration

This is configured in Jira/GitHub settings, not by a file in this project. Connect the GitHub repository to Jira and reference real Jira issue keys in commit messages, for example:

```powershell
git commit -m "WEB-1 Add registration page"
```

Use the actual issue key generated by your Jira project; do not assume it is WEB-1.

## Q7 — Build and run Docker

```powershell
docker build -t devops-webapp:1.0 .
docker run -d --name webapp-container -p 8083:3000 devops-webapp:1.0
```

Open http://localhost:8083.

To stop and remove the container:

```powershell
docker rm -f webapp-container
```

## Q8–Q9 — Jenkins

The root `Jenkinsfile` is a Declarative Pipeline for a Windows Jenkins agent. It checks out the repository, installs npm dependencies, runs tests, builds the Docker image, and deploys the container on host port 8083.

Jenkins must be able to run `node`, `npm`, `git`, and `docker`. The Windows account running the Jenkins service must have access to Docker Desktop. If Jenkins is running on a Linux agent, replace `bat` with `sh` and configure Docker access for that agent.

## Q10 — Kubernetes

The `k8s/deployment.yaml` file defines a two-replica Deployment and a NodePort Service.

For Docker Desktop Kubernetes, build the image locally first:

```powershell
docker build -t devops-webapp:1.0 .
kubectl apply -f k8s/deployment.yaml
kubectl get deployments
kubectl get pods
kubectl get services
```

Open http://localhost:30080 if your Docker Desktop Kubernetes setup exposes the NodePort locally.

To remove the Kubernetes resources:

```powershell
kubectl delete -f k8s/deployment.yaml
```

## Q11 — GitHub Actions

The workflow at `.github/workflows/ci.yml` runs on pushes to `main` and `feature-login`, and on pull requests targeting `main`. It installs dependencies and runs the tests.

## Important notes

- Jira project setup, sprint creation, and Jira/GitHub linking are performed in the Jira/GitHub web interfaces; they cannot be completed by these source files alone.
- Replace example GitHub repository URLs with your own.
- Do not commit passwords, access tokens, or other secrets.
- Capture your own screenshots of successful task execution for CAT evidence.
